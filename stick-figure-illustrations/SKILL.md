# Stick Figure Illustrations

## 核心定位

把创作者内容里的观点、流程、状态、对比和隐喻，转成清晰、轻量、可复用的火柴人草图解释插画。

这不是某个角色 IP，也不是个人作者风格复刻。默认人物必须是匿名火柴人：圆头、线条身体、简单四肢、无品牌身份、无固定名字，但不能是无表情站桩。默认每个人物保持清楚的人体结构：一头、一躯干、两臂、两腿，不要意外生成多手、多脚或肢体粘连。只有当画面明确要表达“很忙”“多任务”“全能”这类状态时，才可以有意使用多手、动作残影或重复肢体，并且要让读者看出这是表达手法，不是画错。默认要用极简眉眼、嘴线、头部倾斜、手势和身体姿态传达情绪。除非用户明确要求“不要人物”“只要图标”“只要抽象图形”，否则生成图里应该以火柴人为主要视觉主体。

文章配图的目标是提升阅读观感、节奏和理解，不是把图堆进文章。只有当插图能让读者停顿、看懂、记住或缓解长文疲劳时才建议加入；如果没有合适位置，应该明确建议少配或不配。

用户不需要重复写基础视觉要求。只要用户给出观点、文章、场景或想表达的意思，就按默认规则生成：`16:9` 画幅、白底或透明白底、黑色线稿、一个克制点缀色、以中性火柴人为主体、用简单表情和姿态表达情绪。只有当用户明确指定画幅、背景、点缀色、人物形式或文字密度时，才覆盖默认规则。

默认追求表现力，不追求“字越少越好”。除非用户明确要求“无文字”“不要标注”或场景必须避开本地化文字，否则默认要加入能帮助理解的短标注：短标题或 punchline、关键物件标签、状态词、动作词或对比词。文字必须增强情绪、对比、节奏或记忆点；不要变成段落说明、满屏标注或 PPT 模板。

当用户要求“公众号封面”“封面图”“头图”“thumbnail”或给出 `2.35:1`、`21:9` 这类宽画幅时，默认走“编辑草图封面”而不是“排版海报封面”：先把标题里的抽象观点转成一个具体动作或瞬间，让火柴人和场景承担主要表达。标题可以是一句手写感短标题、画面中的标签，或预留给后期排版的干净留白；不要生成左侧大标题、右侧人物图标、顶部品牌条、粗体副标题堆叠的营销模板。

## 硬性边界

- 不出现特定作者名、特定案例名或任何外部参考措辞。
- 不画固定吉祥物、高识别度角色、块状填充人物或表情包角色。
- 不让正常人物出现多手、多脚、断肢、粘连肢体或数量不明的手脚；除非主题明确是忙碌、多任务或全能表现。
- 不要求固定多色批注系统。默认只用黑色线稿加 1 个点缀色。
- 不复刻任何已知创作者、插画师、品牌、IP 或公开示例的构图与语气。
- 不把图做成复杂 PPT 信息图、正式架构图、海报 KV、儿童卡通或商业矢量插画。
- 不把公众号封面做成模板化海报：避免大号数字字体/粗体标题接管画面、左文右图分栏、品牌 logo 栏、装饰下划线、孤立人物摆拍和空泛卖点文案。

## 工作流

### 1. 读内容，找视觉锚点

先读用户给的文章、Markdown、文档、截图、主题或链接内容。提炼：

- 核心观点
- 读者卡住的地方
- 能改善阅读观感和节奏的停顿点
- 适合被画出来的动作、状态、对比或路径
- 不适合配图、只适合文字解释的部分

不要平均配图。优先选真正帮助理解或传播的视觉锚点：关键判断、前后对比、步骤转换、输入输出、常见错误、决策分岔、角色困境、成果展示。

### 2. 先出 shot list

除非用户明确说“直接生成 / 现在生图 / 不要规划”，否则先输出 shot list。每张图写清楚：

- 放置位置或使用渠道
- 画幅；未指定时默认 `16:9`
- 图的主题
- 核心意思
- 构图模式
- 火柴人在做什么
- 火柴人是什么情绪
- 主要元素
- 建议标注；默认写出可直接放进图里的短标题、物件标签和状态词，不能只写“少量标注”
- 优先级

默认 3-6 张候选。短内容可以 0-2 张；长文或课程可扩到 8-10 张，但必须说明每张的用途。不要为了凑数量而推荐装饰图。

shot list 格式优先使用 `references/shot-list-schema.md`。如果用户指定场景模式，先读取 `references/presets.md` 再规划。

每次输出 shot list 后，必须追加 `下一步` 区块，告诉用户现在可以直接回复什么。不要让输出停在表格。至少给出：

- 推荐先生成哪一张，以及一句原因。
- 可直接复制的回复命令，例如 `生成 #1`、`生成 #1 和 #2`、`调整 #1：不要文字，用蓝色点缀色`、`先不生成，重新检查插图位置`。
- 如果不建议加图，给出 `不生成，保持文章原样` 或 `重新检查另一版文章` 这类下一步。

### 3. 单张生成

如果用户明确要求“生成 / 输出 / 做图 / 直接画”，直接为每张图单独调用图像生成工具。不要把多张图拼在一张里，除非用户要求轮播总览或分镜板。

如果用户只给了标题就要求生成封面，先在内部提炼一个可画场景：谁被什么问题卡住、什么东西被揭开/整理/连接/压缩、结果如何一眼可见。提示词里必须写出这个场景动作，不要把标题拆成大字版式后再随便放一个火柴人。

每张图只表达一个核心意思。提示词必须包含：

- 目标渠道和画幅；用户未指定时使用 `16:9`
- 有情绪的中性火柴人角色，且默认作为画面主体
- 正常人物的四肢数量清楚：两臂、两腿；不要意外多手、多脚或肢体粘连
- 用极简表情和姿态把情绪读清楚
- 简洁黑色线稿
- 一个克制点缀色；用户未指定时自动选择，不要求用户填写
- 大量留白
- 默认加入表达性短标注：1 个短标题或 punchline，2-5 个物件/状态/动作标签；只有用户明确要求无文字或纯图时才生成无文字版
- 物件和路径要有足够说明，避免读者只能猜画面含义；标注要短、有趣、能服务观点
- 公众号封面/宽封面要以一个可记住的草图场景为主；标题只作为手写感短句、画中标签或后期排版留白。明确禁止模板化的左文右图封面、大号粗体标题、品牌条、营销副标题和装饰性下划线
- 禁止第三方 IP、固定角色、特定作者风格、复杂 PPT 感

### 4. 文章观感优化配图

如果用户要求“给文章找插图位置并同时生成图片 / 一键配图 / 直接给插入位置和图片”，目标是让文章观感更好，而不是塞满插图。不要停在 shot list。先快速完成视觉锚点和阅读节奏筛选，再为 `P0` 和明确能改善阅读体验的 `P1` 图片逐张生成。如果没有合适位置，明确说不建议强行加图。

每张图交付时必须包含：

- 具体插入位置：章节名，或插在某段/某句之后。
- 生成后的图片展示；如果当前环境不能生图，改为给出可直接用于生图的完整提示词，并明确说明未生成。
- Markdown 插入代码，例如 `![图片说明](./assets/article-slug-illustrations/01-topic.png)`。
- 一句话说明这张图如何改善阅读观感、节奏或理解。

### 5. 按场景调整

根据用户目标选择输出形态：

- 文章/Newsletter：正文解释图，信息密度低，帮助读者停顿理解。
- 公众号封面/宽封面：优先一个强动作场景，适合 `2.35:1` 或用户指定宽画幅；人物和道具是主体，文字只保留手写短标题、关键标签或留白位，避免做成模板海报。
- 社媒轮播：每页一个动作或对比，文字更短，主体更大。
- PPT/Keynote：可作为章节过渡、观点旁图、轻量流程图，避免喧宾夺主。
- 产品文档：强调状态、路径、错误恢复和用户任务。
- 教程/课程：一步一图，动作明确，可复用同一人物比例。
- 开源项目：突出安装、贡献、issue、release、维护者协作。
- SaaS 界面：空状态、错误页、成功页、加载页、权限页、导入页。

更多场景见 `references/use-cases.md`。

### 6. 检查与迭代

生成后读取 `references/qa-checklist.md`。如果出现以下问题，重生成或局部编辑：

- 人物像某个固定 IP 或吉祥物
- 画面太像 PPT 模板
- 文字只是堆砌，没有增强表达力
- 关键物件、路径或状态没有标注，导致画面看起来空、无趣或需要猜
- 公众号封面变成通用标题卡、PPT 封面或营销海报，尤其是左侧大标题 + 右侧孤立火柴人的构图
- 元素太满
- 点缀色超过一个主色
- 火柴人只是装饰，没有承担动作
- 火柴人没有可读情绪，像无表情占位符
- 正常人物出现多手、多脚、断肢、粘连肢体或看不清手脚数量；如果不是在表达忙碌、多任务或全能，必须重生成更干净的人物结构
- 可被看出在模仿某个现成风格

### 7. 保存交付

如果用户在 workspace 内工作，把最终图保存到：

```text
assets/<project-or-article-slug>-illustrations/
```

按顺序命名：

```text
01-topic-name.png
02-topic-name.png
```

不要覆盖已有资产，除非用户明确要求替换。

## 输出口径

策略输出要短、可执行。生成后的交付包含：

- 生成了几张
- 每张图适合放在哪里
- 每张图的 Markdown 插入代码
- 保存路径
- 是否有需要重画或删字的图

只输出规划时，也必须包含下一步操作提示，避免用户不知道接下来该如何生成或调整。

不要讲风格理论。创作者要的是能马上用的图。
