# Visual System

## 一句话

中性、清爽、可品牌化、带情绪的火柴人草图解释插画：黑色线条讲清动作和情绪，一个点缀色提示重点，短标注让物件、状态和转折一眼能懂。

## 人物规范

- 默认人物必须是匿名火柴人：圆头或简化头部，线条身体，线条手臂和腿。
- 正常人物必须保持干净的人体结构：一头、一躯干、两臂、两腿；不要意外出现多手、多脚、断肢、粘连肢体或数量不明的手脚。
- 只有当主题明确表达“很忙”“多任务”“全能”时，才允许有意使用多手、重复手臂、动作残影或夸张肢体，并且要通过姿态或标注让读者看出这是表达手法。
- 用户没有特别指定人物形态时，不要切换成抽象图标、普通物件草图、固定吉祥物或其他角色。
- 人物默认必须有可读情绪，不要画成无表情站立占位符。
- 人物表情保持极简，只用一两笔：点眼、短线嘴、眉线。
- 优先用表情和姿态一起表达情绪：头部倾斜、肩膀角度、手势、身体前倾或后仰、轻微张力线。
- 人物没有名字、没有固定服装、没有固定性格、没有 IP 身份。
- 多个人物通过位置、动作、道具或小标签区分，不靠复杂外观区分。
- 火柴人必须承担画面的核心动作：推、拉、递交、对照、搭建、观察、修复、选择、连接、拆分。

## 画面风格

- 用户未指定画幅时，默认使用 `16:9`。
- 只有当用户明确指定，或使用 carousel、saas-state 等特定 preset 时，才改用对应画幅。
- 背景默认纯白或透明白，不加纸纹、渐变、阴影、复杂材质。
- 线条以黑色为主，像细记号笔或白板笔，不追求精致插画质感。
- 主体保持清楚，空白要足够，让图能嵌入文章、PPT、网页或社媒。
- 一张图只表达一个动作、状态、对比或路径。
- 每张图最好有一个清楚但克制的情绪状态，例如困惑、松一口气、犹豫、专注、安心或惊讶。
- 允许轻微手绘感，但不要做成某个作者的个人手绘风格。

## 色彩

- 默认：黑色线稿 + 1 个克制点缀色。
- 点缀色由用户品牌决定；未指定时自动选择适合内容的温和颜色，不要求用户填写。
- 点缀色只用于路径、重点、按钮、结果、警告或当前步骤。
- 不使用固定多色批注系统，不把颜色变成风格签名。

## 文字

- 默认追求表现力，不追求“字越少越好”。
- 除非用户明确要求无文字，默认加入可读短标注：1 个短标题或 punchline，2-5 个物件、状态、动作或结果标签。
- 文字应该增强情绪、对比、节奏或记忆点，可以是短标题、状态词、对比词、步骤词、物件标签或一句 punchline。
- 关键物件、路径、当前步骤、障碍和结果要优先标注，避免读者只能猜画面含义。
- 观点图、正文解释图可以使用短标题加若干关键词；教程、步骤、对比、README 和轮播应该更明确地标出步骤和物件。
- 标注不要变成段落说明，不要满屏铺字，也不要让文字压过火柴人的动作。
- 中文、英文或双语取决于用户内容。
- 社媒和封面图可以有一句短标题；正文解释图可以用小标题或状态词，但不要用抢走主体的大标题。
- 如果图像模型容易写错字，先生成带空白标注框或简短关键词版，再用设计工具补字；不要因此默认删掉所有文字。

## 禁止

- 不要固定吉祥物、实心黑色角色、怪物、动物、可爱贴纸、表情包。
- 不要无表情、僵硬站立、只像说明图占位符的火柴人。
- 不要让正常人物出现多手、多脚、断肢、手脚粘连、手脚数量不清或 AI 画错肢体的感觉。
- 不要复杂商业插画、3D、拟物、科技 UI、真实截图、品牌 KV。
- 不要正式流程图模板、过度整齐的 PPT 图表、大量箭头和节点。
- 不要把所有物件都画成无标签图标，导致画面干净但无趣、难懂。
- 不要复刻任何第三方插画风格、创作者 IP、公开示例、知名品牌广告语气。
- 不要使用“某某风格”“像某某画的”这类提示词。
