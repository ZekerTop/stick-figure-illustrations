# Scene Patterns

## 基础模式

每张图只选一种模式。

### 1. Before / After

适合：混乱到清晰、手动到自动、猜测到验证、单点工具到系统工作流。

画法：左侧旧状态，右侧新状态，中间一个小转换动作。火柴人负责移动、整理或比较。

### 2. Path

适合：用户旅程、学习路线、发布流程、从想法到成果。

画法：一条简单路径，3-5 个节点。人物沿路前进或在关键节点做选择。

### 3. Hand-off

适合：团队协作、agent 接力、内容生产链路、客服升级。

画法：两个或三个人物把一个对象传递下去。重点是责任变化，不是节点数量。

### 4. Stack

适合：方法论层级、能力栈、产品架构的高层解释。

画法：几层简单盒子或台阶。人物在搭建、检查或抽出其中一层。

### 5. Split / Merge

适合：分流、聚合、多渠道发布、多版本输出。

画法：一个输入分成多个输出，或多个输入汇成一个结果。用一个点缀色表示主路径。

### 6. Trade-off

适合：速度 vs 质量、自动化 vs 控制、增长 vs 信任。

画法：天平、滑杆、跷跷板或两扇门。人物做选择，而不是站着解释。

### 7. Obstacle

适合：卡点、bug、权限、信息过载、认知负担。

画法：人物被一个具体障碍挡住，并正在寻找绕过、拆开或标记它的方法。

### 8. Loop

适合：反馈循环、复利、迭代、训练、复盘。

画法：一个简单环路，人物在某一段投入动作，结果回到起点但更清楚。

## 隐喻生成方法

1. 把抽象概念变成动作：选择、筛选、压缩、连接、拆分、验证、修复、排队、同步。
2. 把信息变成简单物件：纸片、卡片、盒子、路标、门、台阶、桥、开关、仪表、绳子。
3. 让火柴人执行动作：把卡片放进盒子、推开门、接上线、搬上台阶、从两条路中选择一条。
4. 删除不必要解释：能用动作看懂的，不要再写成长句。

## 避重规则

- 不复用同一主题的老套图：灯泡、火箭、拼图、握手、靶心、巨型漏斗。
- 不用固定角色姿态当签名。
- 不用固定三色批注当签名。
- 不用离题道具强行制造风格；优先清楚，再考虑有趣。
- 每次至少换掉两个维度：场景、道具、人物动作、视角或画幅。
