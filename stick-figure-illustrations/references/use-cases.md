# Use Cases

## 文章与博客

目标：让读者在关键段落停一下，看懂抽象观点。

适合画：

- 核心判断
- 复杂概念的简单隐喻
- 前后对比
- 常见误区
- 一个流程的关键转折

默认输出：16:9 正文配图，白底。文字以表现力为准，用户指定时可改为 3:2。

## Newsletter

目标：让邮件内容更轻、更有节奏。

适合画：

- 本期主题开场图
- 观点总结图
- 一张工具/方法/清单的视觉摘要

默认输出：16:9 横图。用户指定邮件头图时可改为 2:1。文字要有记忆点，但避免被邮箱缩放后看不清。

## 微信公众号封面图

目标：让文章在订阅流里一眼有“这篇讲什么”的记忆点，同时保持创作者手绘草图感。

适合画：

- 标题里的核心反差
- 一个问题被揭开的瞬间
- 混乱信息被整理成路径
- 看似简单结果背后的过程
- 读者踩坑前后的状态变化

默认输出：用户指定比例；未指定时用 2.35:1 宽封面。必须使用图像生成工具产出栅格图。不要用 SVG、HTML 截图、流程图或线框图冒充最终封面。

封面必须先找一个强主场景：大物件 + 人物动作 + 变化结果。标题很长时，改成一句手写短 punchline 或留出后期排版空间，不把全文标题排成海报大字。

## 社媒轮播

目标：每一页只让读者理解一个动作或判断。

适合画：

- 4-8 页连续概念
- 使用前/使用后
- 错误做法/正确做法
- 步骤拆解

默认输出：4:5 或 1:1。人物更大，标注更短。

## PPT / Keynote

目标：辅助演讲，不抢信息层级。

适合画：

- 章节过渡
- 单页观点旁图
- 轻量流程
- 问题状态
- 结论页的行动暗示

默认输出：16:9，文字服务演讲节奏，可以无文字，也可以用短标题、状态词或对比词增强表达。

## 产品文档

目标：解释用户任务和状态，不做营销海报。

适合画：

- 安装步骤
- 导入/导出
- 权限/审批
- 错误恢复
- 空状态
- 成功状态

默认输出：16:9，人物动作明确，道具简单。用户指定 UI 场景时可改为 3:2 或方图。

## 教程与课程

目标：把学习过程拆成可跟随的小动作。

适合画：

- 每一步的操作目的
- 学习前后变化
- 练习任务
- 反馈循环
- 常见卡点

默认输出：16:9 或讲义宽图。可以保持同一人物比例，形成系列感。

## 开源项目

目标：让 README、贡献指南和 release note 更友好。

适合画：

- 安装流程
- issue triage
- pull request review
- maintainer workflow
- roadmap
- release pipeline

默认输出：16:9 或 2:1。避免企业宣传感，保持工程文档气质。

## SaaS 与产品界面

目标：补足空状态、错误页、加载页和 onboarding 的情绪。

适合画：

- empty state
- error state
- permission denied
- upload/import
- sync/loading
- success/completion
- collaboration invite

默认输出：方图、3:2 或透明背景版本。文字谨慎使用，优先保证产品界面可复用和本地化。

## 视频、播客与活动

目标：先做概念草图，再决定是否交给设计师精修。

适合画：

- 主题缩略图草案
- episode concept
- speaker topic
- workshop activity
- 活动流程卡

默认输出：16:9 或 1:1。可以加一句短标题，但避免完整海报设计。
