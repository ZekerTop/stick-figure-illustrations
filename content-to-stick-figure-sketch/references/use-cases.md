# Use Cases

## 文章与博客

目标：让读者在关键段落停一下，看懂抽象观点。

适合画：

- 核心判断
- 复杂概念的简单隐喻
- 前后对比
- 常见误区
- 一个流程的关键转折

默认输出：16:9 或 3:2 正文配图，少字，白底。

## Newsletter

目标：让邮件内容更轻、更有节奏。

适合画：

- 本期主题开场图
- 观点总结图
- 一张工具/方法/清单的视觉摘要

默认输出：16:9 横图或 2:1 邮件头图。文字尽量少，避免被邮箱缩放后看不清。

## 社媒轮播

目标：每一页只让读者理解一个动作或判断。

适合画：

- 4-8 页连续概念
- 使用前/使用后
- 错误做法/正确做法
- 步骤拆解

默认输出：4:5 或 1:1。人物更大，标注更短。

## PPT / Keynote

目标：辅助演讲，不抢信息层级。

适合画：

- 章节过渡
- 单页观点旁图
- 轻量流程
- 问题状态
- 结论页的行动暗示

默认输出：16:9，最好无文字或只有 1-3 个短标签。

## 产品文档

目标：解释用户任务和状态，不做营销海报。

适合画：

- 安装步骤
- 导入/导出
- 权限/审批
- 错误恢复
- 空状态
- 成功状态

默认输出：16:9、3:2 或方图，人物动作明确，道具简单。

## 教程与课程

目标：把学习过程拆成可跟随的小动作。

适合画：

- 每一步的操作目的
- 学习前后变化
- 练习任务
- 反馈循环
- 常见卡点

默认输出：16:9 或讲义宽图。可以保持同一人物比例，形成系列感。

## 开源项目

目标：让 README、贡献指南和 release note 更友好。

适合画：

- 安装流程
- issue triage
- pull request review
- maintainer workflow
- roadmap
- release pipeline

默认输出：16:9 或 2:1。避免企业宣传感，保持工程文档气质。

## SaaS 与产品界面

目标：补足空状态、错误页、加载页和 onboarding 的情绪。

适合画：

- empty state
- error state
- permission denied
- upload/import
- sync/loading
- success/completion
- collaboration invite

默认输出：方图、3:2 或透明背景版本。尽量无文字，方便产品界面本地化。

## 视频、播客与活动

目标：先做概念草图，再决定是否交给设计师精修。

适合画：

- 主题缩略图草案
- episode concept
- speaker topic
- workshop activity
- 活动流程卡

默认输出：16:9 或 1:1。可以加一句短标题，但避免完整海报设计。
